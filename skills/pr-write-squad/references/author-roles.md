# 작성자, 사실 확인자, 처음 읽는 리뷰어

## 작성자

목표는 **리뷰어가 코드를 열기 전에 이 PR이 무엇이고 어디부터 볼지 알게 하는 것**이다.

### 쓰는 법

- 제목: 저장소의 최근 PR 제목 형식(예: `feat(scope): 한 줄 요약`)이 있으면 그대로 따른다. 없으면 "무엇을 한다"를 동사로 끝나게 한 문장, 72자 이내, 마침표 없이.
- 본문은 템플릿(저장소 것이 우선)의 섹션을 모두 채운다. 안내 주석(`<!-- ... -->`)은 지우고 내용으로 바꾼다. 템플릿의 제목 문구는 바꾸지 않는다.
- **무엇을**: 파일 이름을 나열하지 말고 동작이 어떻게 달라지는지 쓴다. 파일은 "먼저 볼 곳"에서만 언급한다.
- **왜**: 이슈나 커밋에 이유가 있으면 그것을 쓴다. 이유를 알 수 없으면 지어내지 말고 "(이유 미확인: 작성자에게 확인 필요)"라고 쓴 뒤 종합자가 사용자에게 묻는다.
- **어떻게 확인했나**: `verification.json`에 있는 것만 쓴다. `passed`는 "실행했고 통과했다", `not_run`은 "실행하지 못했다(이유)"로 쓴다.
- **이번에 하지 않은 것**: 변경이 일부러 하지 않은 것(후속 작업, 범위 밖)을 쓴다. 근거가 없으면 이 섹션에 "없음"이라고 쓰되, 커밋 메시지나 코드 주석(TODO)에 근거가 있으면 반드시 쓴다.
- **위험과 되돌리는 방법**: 영향받는 동작과 되돌리는 방법(예: 이 커밋을 revert)을 쓴다. 마이그레이션, 설정 변경, 공개 인터페이스 변경이 있으면 반드시 쓴다.

### 주장 목록 (`claims.json`)

본문에서 **검증 가능한 문장**마다 한 건씩 뽑는다. 아래 종류가 대상이다.

| kind | 예 |
|---|---|
| `change` | "할인율 인자 `discount`를 추가했다" |
| `behavior` | "`discount=1.0`이면 합계가 0원이다" |
| `test` | "경계값 테스트를 추가했다" (추가한 테스트가 있는지) |
| `scope` | "DB 스키마는 바꾸지 않았다" |

각 주장은 `id`, `text`, `kind`, 작성자가 생각하는 근거 위치(`evidence`, `파일:줄`)를 가진다. `verdict`는 비워 둔다(사실 확인자가 채운다).

실행 결과(통과/실패)는 주장이 아니라 `verification.json`에 둔다.

## 사실 확인자

작성자의 문장을 믿지 말고 **diff에서 반박하려고 해 본다**. 입력은 주장 목록과 diff(및 저장소 파일)뿐이다.

1. 주장마다 diff와 해당 파일을 직접 열어 확인한다.
2. `SUPPORTED`: 주장이 코드로 확인된다. `evidence`에 `파일:줄`을 적는다.
3. `UNSUPPORTED`: 코드와 다르거나 diff에 없다. `note`에 무엇이 다른지 한 문장으로 적는다.
4. `UNCERTAIN`: 코드만으로 판단할 수 없다. 무엇이 있으면 판단할 수 있는지 적는다.
5. `behavior` 주장은 입력과 결과를 코드로 따라가 본다. 말만 그럴듯하고 실제 분기가 다르면 `UNSUPPORTED`.
6. `scope`("~는 바꾸지 않았다") 주장은 diff 전체에서 해당 파일이나 동작이 정말 없는지 찾아본다.
7. 사실 확인자는 작성자의 본문을 보지 못한다. 본문에 있는데 주장 목록에서 빠진 문장이 있는지는 **종합자**가 본문을 문장 단위로 훑어 `claims.json`과 대조해 확인하고, 빠진 것은 주장으로 추가해 사실 확인자에게 다시 보낸다.

반환은 갱신된 `claims.json` 배열 하나뿐이다.

## 처음 읽는 리뷰어

제목과 본문만 읽고(코드, diff, 커밋 보기 금지) 다음에 답한다. 모르면 "알 수 없음"이라고 쓴다.

1. 이 PR은 무엇을 바꾸는가?
2. 왜 바꾸는가?
3. 어떻게 확인했는가? 확인하지 못한 것은 무엇인가?
4. 이 PR이 바꾸지 않는 것은 무엇인가?
5. 코드에서 어디를 먼저 봐야 하는가?

"알 수 없음"이 하나라도 있으면 그 질문이 본문의 부족한 곳이다. 어디를 어떻게 보강하면 좋을지 한 문장씩 적는다. 코드를 추측해서 대신 채우지 않는다.
