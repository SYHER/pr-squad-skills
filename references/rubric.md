# 평가 기준

## 지적 등급

| 등급 | 의미 | 예 |
|---|---|---|
| C0 | 머지 차단. 잘못된 결과, 데이터 손실, 보안 취약점, 크래시 | 인증 확인 누락, 경계값에서 잘못된 금액 계산, 예외 삼킴으로 데이터 유실 |
| C1 | 수정 권장. 지금은 안 터져도 곧 문제가 될 것 | 실패 경로 테스트 없음, 입력 검증 부재, 오류 처리 누락 |
| C2 | 제안. 판정에 영향 없음 | 네이밍, 중복 코드, 린터 설정에 없는 스타일 |

등급 판단이 애매하면 한 단계 낮춘다. 등급을 올리려면 구체적인 실패 시나리오(입력 → 잘못된 결과)를 `scenario`에 적어야 한다.

## 등급 부여 규칙

### 1. 지적 하나에는 원인 하나

한 건의 지적에 서로 다른 두 문제를 묶지 않는다. 특히 **구현의 결함**과 **테스트의 부재**는 따로 쓴다.

| 문제 | 어느 관점이 쓰나 | 등급 기준 |
|---|---|---|
| 코드가 잘못 동작하거나 검증을 강제하지 않는다 | 정확성 또는 보안 | 구현 위험도로 정한다 |
| 그 동작을 지켜 주는 테스트가 없다 | 테스트 | 아래 2번 규칙으로 정한다 |

예: "서버가 날짜 범위를 강제하지 않는다"는 정확성/보안 지적이고, "경계값 테스트가 없다"는 테스트 지적이다. 한 줄에 같이 쓰지 않는다. 두 리뷰어가 같은 코드를 가리키면 종합 단계에서 병합하지 말고, 원인이 다르면 별개 지적으로 둔다. 원인이 같으면(같은 결함의 두 표현) 병합한다.

### 2. 테스트 부재 지적의 등급

테스트 리뷰어는 구현을 심판하지 않고 **회귀했을 때 아무도 모르고 지나가는 정도**로 등급을 정한다. 다음 세 조건을 **모두** 만족할 때만 C1이고, 하나라도 빠지면 C2다.

- (a) PR이 새로 만들었거나 바꾼 분기·경로에 대한 테스트다. 기존 코드의 오래된 공백은 해당하지 않는다.
- (b) 그 분기가 회귀하면 데이터 삭제, 덮어쓰기, 잘못된 금액, 권한 우회처럼 되돌리기 어려운 결과가 난다(C0 수준의 결과).
- (c) 다른 안전망이 없다. 기존 테스트, 타입 검사, 런타임 검증, 호출 경로상 제약 중 어느 것도 같은 회귀를 막지 못한다.

| 예 | 등급 | 이유 |
|---|---|---|
| 새 분기가 Local이면 날짜를 지우는데, 그 분기를 호출하는 테스트가 없고 상위 테스트는 함수를 mock한다 | C1 | a, b, c 모두 충족 (날짜 삭제/되살아남) |
| 새 UI 선택 상자의 시작 값이 바뀌면 여러 Asset의 날짜가 한꺼번에 지워지는데 테스트가 없다 | C1 | a, b, c 모두 충족 |
| 새 파싱 헬퍼의 경계값(범위 끝, 시간 포함 문자열) 테스트가 없다 | C2 | b 미충족: 회귀해도 잘못된 값이 저장될 뿐 삭제나 덮어쓰기는 아니다. 서버 검증 부재는 별도 구현 지적으로 낸다 |
| 읽기 경로의 반환 타입이 바뀌었는데 변환 테스트가 없다 | C2 | b 미충족, 호출하는 쪽 테스트가 간접적으로 걸린다 |
| 기존 코드의 미커버 줄 | 보고하지 않음 | a 미충족 (C0이 아니면 보고 대상이 아니다) |

(b)가 애매하면 `scenario`에 "회귀했을 때 어떤 입력이 어떤 잘못된 결과를 내는가"를 한 문장으로 적게 하고, 적지 못하면 C2로 낮춘다.

### 3. C0/C1 공통 최소 요건

- C0: 실제 호출 경로로 도달 가능한 입력과 그 결과(잘못된 출력, 손실, 우회)를 코드 인용과 함께 `scenario`에 적을 수 있어야 한다. 도달 경로를 확인하지 못하면 C1로 낮추고 `UNCERTAIN` 후보로 둔다.
- C1: 현실적인 입력에서 문제가 생기는 경로를 적을 수 있어야 한다. "나중에 문제가 될 수 있다"만으로는 C2다.
- 스타일, 네이밍, 중복, 구조 개선은 어떤 경우에도 C2다. 구조 문제 때문에 버그가 날 것이 분명하면 그 버그를 정확성 지적으로 따로 쓴다.

## 판정 규칙

점수가 아니라 규칙으로 정한다. `scripts/validate_findings.py`가 같은 규칙을 계산한다.

1. 검증을 통과한(`CONFIRMED`) C0이 1건 이상: `REQUEST_CHANGES`
2. 위에 해당하지 않고 `CONFIRMED` C1이 1건 이상: `COMMENT`
3. 그 외: `APPROVE`

`UNCERTAIN` 지적은 판정에 넣지 않고 "확인 필요"로만 표시한다. `REJECTED`는 보고하지 않는다. C2는 개수와 관계없이 판정에 영향이 없다.

## 관점별 점수 (참고용, 판정과 별개)

각 관점을 10점 만점으로 매긴다. 판정은 위 규칙이 정하고, 점수는 사용자가 PR의 상태를 한눈에 보기 위한 요약이다.

| 점수 | 기준 |
|---|---|
| 9~10 | 확인된 지적 없음 또는 C2만 있음 |
| 7~8 | 확인된 C1 1건 |
| 5~6 | 확인된 C1 2건 이상 |
| 0~4 | 확인된 C0 있음 |

C0이 있는 관점은 다른 관점이 만점이어도 총평에서 상쇄하지 않는다.

## 실행하지 못한 검증

테스트나 린터를 돌리지 못했으면 해당 관점 점수 옆에 `(미실행)`을 붙이고, 보고서의 "이번 리뷰가 보지 못한 것"에 이유를 적는다. 실행하지 못한 것을 통과한 것처럼 쓰지 않는다.
